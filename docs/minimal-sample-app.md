# 最小示例 App 草案

## 目标

最小示例 App 用于证明 BLE 中文 API 可以被普通业务 App 接入。它不实现 BBS、不实现剪刀石头布，只验证最核心的通信流程。

## 页面元素

- 顶部显示当前连接状态。
- 显示附近邻机数量。
- 一个文本输入框。
- 一个发送按钮。
- 一个收到消息列表。
- 一个调试开关，用于显示最近 BLE 事件。

## 基本流程

1. App 启动后请求必要权限。
2. 用户点击“启动通信”。
3. App 调用 `通信器.启动()`。
4. 两台设备互相发现并连接。
5. A 输入文本并点击发送。
6. B 的收到消息列表出现该文本。
7. B 输入文本并点击发送。
8. A 的收到消息列表出现该文本。
9. 用户点击“停止通信”。
10. App 调用 `通信器.停止()`。

## 示例业务消息

```kotlin
data class 文本消息(
    val 编号: String,
    val 正文: String,
    val 发送者: String,
    val 时间戳: Long
)
```

## 示例调用

```kotlin
val 通信器 = 蓝牙通信器(
    上下文 = context,
    配置 = 示例通信配置,
    编解码器 = 文本消息Json编解码器()
)

通信器.收到消息流.collect { 消息 ->
    消息列表.add(消息)
}

通信器.发送(
    文本消息(
        编号 = UUID.randomUUID().toString(),
        正文 = 输入内容,
        发送者 = 本机编号,
        时间戳 = System.currentTimeMillis()
    )
)
```

## 测试矩阵

| 场景 | 预期 |
| --- | --- |
| A 发给 B | B 收到文本 |
| B 发给 A | A 收到文本 |
| A 连续发送两条 | B 收到两条 |
| B 蓝牙关闭后发送 | 返回发送失败 |
| 停止通信后发送 | 返回发送失败 |
| 重启通信后发送 | 可以重新收发 |

## 不纳入最小示例

- 数据库存储。
- 历史消息补发。
- 多设备 mesh。
- 游戏规则。
- 复杂 UI。
- library 远程发布。

这些内容可以在 library 基础行为稳定后再扩展。
