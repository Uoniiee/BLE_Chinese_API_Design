# Issue #1 可靠传输层整理计划

本阶段对应 GitHub Issue #1，目标是把 v0.5.7 已验证的最小示例
整理成更可复用的 library 传输层能力。

当前状态：`v0.6.1-debug` 已完成并由维护者三机验证通过。

## 目标

将示例 App 中已经通过真机测试的 BLE 发现、连接、订阅、发送与去重
流程收敛到 `:ble_chinese_api` library 中，让后续业务 App，例如
剪刀石头布，只需要使用稳定的中文 API，不需要重复处理底层 BLE 细节。

本阶段按 Issue #1 范围执行。

## 范围

- 保留 v0.5.7 已验证的稳定设备 ID。
- 保留按稳定 ID 去重的邻机识别方式，避免 Android 随机蓝牙地址变化
  导致重复连接。
- 保留通信方向仲裁，减少双向同时连接造成的碰撞。
- 只有通知订阅真正写入成功后，才登记为可写连接。
- 增加发送队列，避免多条消息同时写入同一个 GATT 特征。
- 使用 `onCharacteristicWrite` 串行化写入结果。
- 增加发送超时和失败反馈。
- 增加邻机老化，清理长时间没有出现或已经断开的邻机。
- 整理 library 使用文档和调试记录。

## 已完成

- 稳定应用层设备 ID。
- 按稳定 ID 去重的邻机识别。
- 通信方向仲裁。
- 通知订阅确认后再登记可写通道。
- 发送队列。
- `onCharacteristicWrite` 串行化写入。
- 5 秒发送超时和失败反馈。
- 60 秒邻机老化。
- 7 字节传输帧头和消息编号去重。
- 横竖屏切换时保留示例 App 日志与状态。

## 暂不包含

- 不实现标准 Bluetooth Mesh 协议。
- 不实现完整多跳路由、组网寻路或可靠广播洪泛。
- 不直接改造剪刀石头布业务 App。
- 不把示例 App 的界面打磨作为主要验收目标。

## 验收标准

- Android library 和 sample app 能通过 Gradle 构建。
- 两台 Android 真机可完成最小文本双向收发。
- 示例 App 能显示关键连接、订阅、写入、超时和失败状态。
- 文档说明已验证行为、已知限制和后续可扩展方向。

## 验收结果

- 本地 A/C 两台 Android 真机可互发中文短消息。
- 本地 A/B/C 三台 Android 真机可完成短消息互通。
- 维护者反馈 `v0.6.1-debug` 三机测试通过。
- 测试中未再出现原始 `BCAPI1...` 帧文本暴露到界面的问题。
- 测试中未再出现自己收到自己消息的重复显示问题。
- 测试中未再出现已验证路径上的写入超时。
- 维护者已确认验收通过。

## 风险与注意事项

- 不同 Android 厂商对 BLE 扫描、广播、连接和权限的行为差异较大。
- Android 12 及以上需要特别关注附近设备权限。
- 部分系统仍可能把 BLE 扫描和定位能力关联在一起。
- 随机蓝牙地址会变化，不能只依赖扫描到的 MAC 地址识别设备。
- 多机同时启动时可能发生连接碰撞，需要通过角色和稳定 ID 仲裁。
- 示例 App 中的已连接数量可能代表通信通道数量，不一定等于物理设备数。

## 实施顺序（已完成）

1. 先把 v0.5.7 的稳定 ID、方向仲裁、订阅确认和去重逻辑整理到 library。
2. 再加入发送队列与 `onCharacteristicWrite` 串行化。
3. 然后补充超时、失败反馈和邻机老化。
4. 最后更新使用文档、调试记录和测试结论。
